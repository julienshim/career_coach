# Changelog

Date + version (YYYY.MM.DD.N), newest first. One entry per commit that touches the mechanism, written at commit time, covering every mechanism change since the previous commit. N = that day's commit number. One line per change: what changed and why. Mechanism only — hats, standards, AGENTS, README, the registry contract. Instance changes are recorded in the hat logs and the ledger, not here. The entry is user-agnostic: the "why" names the class of failure a rule prevents, never an instance fact or inference (no dates beyond the entry's own version, no counts, no incident narrative). Uncommitted work lives in `git diff` and the hat logs; this file records what is in the commits. The design narrative — how and why the structure became what it is — lives in the README's How the System Evolved.

## 2026.11.08.2

- **CI:** the test matrix drops the oldest supported python — the latest runner image no longer ships it in its version manifest, so the job failed at interpreter installation, before the suite ran, and read as a code failure. The matrix now covers the installable versions; the floor is verified in the development environment, where the suite runs every session. Prevents the class of failure where a broken interpreter install masks (or fakes) a code failure.

## 2026.11.08.1

- **Store (new — the data layer's system of record):** the mechanism gains its own tooling — `scripts/store.py` + `tests/` (user-agnostic, python3 stdlib only, test-first) — an sqlite store (the `store` concept, user data under `instance/`) holding `events` (append-only; no UPDATE or DELETE path exists), `threads` (derived status per company + role; never hand-set), and `run_logs` (the hat logs); named ops (`migrate`, `log-event`, `log-run`, `pickup`, `status`, `caps`, `divergence`, `export-ledger`, `export-logs`, `export-claim`) are the only writer. Prevents the class of failure where the data layer is hand-edited text: mechanical field-structure errors, PII in notes, an event logged without its state flip, and counts or drift that only a full audit catches.
- **AGENTS:** the "no new code" rule rewritten — the only code in the repo is the mechanism's own tooling (`scripts/`, `tests/`), user-agnostic like the hats; the user's own code still lives outside, referenced by path only; user data lives in `instance/`. Prevents the class of failure where the mechanism's data-access layer is mistaken for the user's work code and kept outside the product a new user should get with the hats.
- **Standards (§ The store, new):** the ops contract, the invariants (append-only events, the flip atomic with the insert, the TSVs as generated exports), the flip table (thread state derived from the outcome vocabulary — a re-apply flips a rejected thread back to submitted on the same thread), the PII refusal at write time, and the interaction model (the store is the agent's interface for state; the TSVs are regenerated at the end of any run that wrote events, so the file on disk is never stale and the user can open them any time). Prevents the class of failure where thread state is smeared across several files and a stale copy stands next to a newer fact.
- **Standards (the state flip):** the rule now names the op — `log-event` performs the store's half of the flip atomically; the markdown state files are the run's half, in the same run.
- **Standards (the drift scan):** the state-vs-event class gains a stored check — `divergence` (QA section presence, hub live-state recency, cast naming; a missing state file is drift, never a crash); the grep battery covers the other classes.
- **Standards (layering table + ledger rules):** the dated company event, the thread status, the per-hat "left off", and the application limits now name the store (the TSVs are its generated exports); the hub README keeps the dated narrative live state; "a written row is never edited" is structural (the store has no edit path).
- **Sourcing hat:** Step 0 pre-check runs on the store (`caps`, `status`); Step 7 logs through `log-event` (the note contract, the PII refusal, the atomic flip) with the deliberation in `log-run`; the run's confirm step ends with the export regeneration so the TSVs on disk are never stale.
- **Interview hat:** the outcome step logs through `log-event` (the thread state flip rides the op) plus the thread hub README.
- **Hats (all six):** the Log step is `log-run` into the store; `pickup --hat` is the "left off"; the log TSVs are generated exports, never hand-edited.
- **Registry contract + MANIFEST:** the `store` concept registered and resolved (`instance/db/`); the `ledger` and `logs` concepts marked as the store's generated exports; the standard layout gains the db directory.
- **Store op naming:** the benefit-claim export op is named for the concept (`export-claim`), never for a specific user's agency or program — the mechanism names the class of report; the instance's config names the program.
- **CI (new):** a GitHub Actions workflow runs the store's test suite on push and pull request across the supported python3 versions, so the mechanism's tooling is machine-checked on every change, not only locally.
- **README:** the two-layers list, the file tree, the state locations, and the evolution narrative now name the store (the ops, the append-only events, the derived thread states, the generated exports); the setup names python3; the evaluation section points at the suite and the CI. The examples stay generic — the CI status badge is the one named exception to the user-agnostic gate, since a badge must name the repo it reports on.
- **.gitignore:** the header's tracked list names `scripts/`, `tests/`, and the CI workflow; sqlite artifacts are ignored at any depth; in-progress working artifacts that carry instance data are ignored so they can never be staged by accident.

## 2026.11.07.1

- **Standards + Interview hat (distillation end state):** the rejected-interview distillation rule now states the end state of a closed thread — the company directory is torn down (no permanent archive), and the reusable learning is folded into the standard answer banks, which are improved with every distillation. Prevents the class of failure where a closed thread's end state is left implicit, so the next agent cannot tell what an archived or deleted thread is supposed to mean.
- **Sourcing hat (Step 5, field sizing):** the field-type sizing rule is now stated once in the step (it carried restated copies of the same rule). Prevents the class of failure where a restated rule drifts from its first statement and the agent deliberates across the copies.
- **AGENTS (standing rules):** the standing-rules summary is now explicitly a summary — the canonical wording lives in the standards operating rules, which win on disagreement. Prevents the class of failure where an entry-point summary and the rulebook drift apart and the agent follows the older copy.
- **Standards (single source, write-time half):** the single-source rule now states that a fact with a home is written as a pointer, never restated as the value — restating for local context is how the copies drift. Prevents the class of failure where a restated value drifts from its home and both copies circulate as current.
- **Standards (the state flip):** new operating rule — a ledger row for a state-changing event is incomplete until the same run flips every state-carrying file that names the thread (the QA status line, the strategy cast line, the company standing call, the thread hub's live state); the state files are derived from the ledger and updated in the run that writes the event, never in a later cleanup. Prevents the class of failure where an event is logged and the derived state never flips, so a stale status stands next to a newer fact.
- **Standards (distillation, the close in one pass):** the rejected-interview distillation rule now states that the close is one pass — the close run writes every close record from the same facts (ledger row, hub, cast line, distillation) and checks first whether the thread is already marked closed anywhere. Prevents the class of failure where one close event lands in several files that disagree about it.
- **Standards (the drift scan):** new section — a fixed battery of cheap checks over five drift classes (dead references, state-vs-event divergence, restated values, NDA, superseded state); the mechanism names the classes, the instance holds the concrete checks; any run that writes state ends with the scan over the classes it touched. Prevents the class of failure where drift accumulates silently between full audits.
- **Sourcing hat (Step 7, Log):** the Log step now names the state flip — every state-carrying file that names the thread is updated in the same run; a ledger row without it is an incomplete log (the canonical rule stays in the standards; the hat names it once, no restatement). Prevents the class of failure where the logging step ends before the derived state is flipped.

## 2026.11.05.1

- **Standards (source ruling):** a user ruling on sources is promoted from the instance into the mechanism — Evidence-first now states a source is exactly two kinds: the code/workspace (the user's actual work) and the user (stated or confirmed, with a date); a draft the user wrote (resumes, cover letters, self-descriptions) is testimony to verify against those two, never a source itself. Root cause of the contamination this rule prevents: a user's own application drafts had been accepted as the EVIDs' source, and a later deletion left the citations dead.
- **Standards (EVID schema):** "the claim, the artifact, the numbers, the date, the source" → "the claim, the numbers, the date, the provenance" — a workspace artifact and/or a user-stated/confirmed value with a date, never a draft the user wrote.
- **Standards (unit schemas):** the citation-style rule — provenance in any unit cites, it does not inventory: an EVID ID and/or a workspace path, never a list of documents (document inventories had spread across instance units as practice the schema never constrained).
- **Standards:** new operating rule "Deletion is an event" — deleting a file the brain references is a mechanism event; the same run re-scans for the filename, the short name, and the phrases that pointed at it, and fixes or flags each reference (a deletion had left dead references in place until a later audit found them).
- **Standards:** new operating rule "Write for the now" — files carry the current confirmed truth; a superseded value or a gone source is deleted, no tombstones, no "historical" annotations, no quotes from deleted files; the record survivors are named (submitted answers verbatim, dated ledger rows, strike/keep decisions).
- **Standards + AGENTS + Sourcing hat:** the ledger note is third-party-safe — what happened, the link, posted comp, location, quoted employer wording, the user's own stated answers; never fit scores, gap lists, lane reads, floors/targets/anchors, internal paths, EVID IDs, or narration; work authorization never restated; a written row is never edited (a later event is a new dated row); the per-application deliberation (fit, comp read, gaps, resume call) goes in the run's log row, not the ledger (the log-events rule, the log-every-submission rule, the AGENTS application-record line, and the sourcing Log step all carry it).
- **Standards (layering table):** "Per-job compensation" → "Per-job posted compensation"; "Company stage/outcome" → "Each dated company event" (ledger only; the strategy cast's dated re-flags are permitted as pointers); new row — a thread's live/pending state lives in the thread-hub README + the owning hat's log row, never the ledger (derived at read time).
- **Standards (response style):** new "Answer the question asked" rule — a confirmation request gets the answer first, in one line; no narrating a near-miss that never happened, no selling a confirmation as a save.
- **Standards + Architect hat (evidence code):** the off-limits rule gains the safe-walk clause — a tree walk prunes `instance/evidence-code/`; a glob that can descend into it (a root `**`, or a harness where root `*` is recursive) is a violation even without inspecting the contents; the architect's pull list names the prune.
- **Registry contract:** the `evidence_code` concept registered; the `evidence` concept's EVID shape aligns to the standards schema (claim, numbers, date, provenance); the `ledger` concept carries the third-party-safe note; `resume_default` drops "plus named variants" (the per-user manifest resolves the file); new § The standard layout — the default `instance/` tree the Discovery hat builds from (a reference instance's career-map README is per-user and does not exist before discovery).
- **Discovery hat:** the layout reference moves to the registry contract's § The standard layout ("never copy another instance's content"); the process fills the identity (identity, career themes, thesis, voice) and splits target roles into their own step 7 (the unit has its own schema home); new drafts-as-testimony lens — the user's old resumes and cover letters are verified against the workspace or a dated user statement, never cited.
- **Sourcing hat:** the Log step names the third-party-safe note contract (the pointer to standards) and moves the per-application deliberation to the run's log row; "a written row is never edited."
- **README:** tree whitespace alignment (3 lines).
- **.gitignore:** the tracked-list comment names `CHANGELOG.md` (the file is tracked; the comment predates it).

## 2026.10.23.2

- **Standards:** the ledger rule rewritten — "Log real events only, on their date": a row is a dated event and says only what was true on its date; no rows for passive waiting; no state observations backfilled into past-dated rows; a thread's live state is derived at read time (last dated event + current date + the cadence in `config`), never logged; pending or inferred state lives in the thread hub README, dated; the ledger may be presented to third parties by the user — every stage/outcome is a factual event, never an inferred state; follow-up cadence and posture come from `config`, and when unset the agent asks — the mechanism takes no posture of its own (the old "no desperation / employer's-market default" framing is gone).
- **Standards:** evidence-first clarified — user responses are evidence: user-verified baselines and user-confirmed values seed the EVIDs, and for experiential claims the user's own words are the record; no artifact is required.
- **Changelog:** versioned scheme (YYYY.MM.DD.N) so multiple change batches on one date stay distinct; scope is mechanism only — instance changes are recorded in the hat logs and the ledger.
